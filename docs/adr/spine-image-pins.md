# Exact image versions for the four spine services

A record of the register, made 2026-11-16. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-15, issue 429. Context: four spine containers ran on moving image tags: caddy on latest, forgejo on 17, radicale on stable, and vaultwarden on latest. A restart could pull a different image with no commit and no review, while every source that the flake builds carries a lock entry (the Declarative Law, docs/flake.md). The nixpkgs of the lock ships the same majors as native units, so a move to native units was the second path of the issue. Decision: each of the four containers pins the exact version that its moving tag resolved to on 2026-11-16: caddy 2.11.9, forgejo 17.0.1, radicale 3.9.1, and vaultwarden 1.37.5. A version bump of a spine service goes through one commit. Each service keeps its pull line, so a re-push of the exact tag still refreshes. The registries held one digest for each moving tag and its exact version, read on 2026-11-16: latest and 2.11.9 of ghcr.io/caddybuilds/caddy-cloudflare, stable and 3.9.1 of ghcr.io/kozea/radicale, and latest and 1.37.5 of vaultwarden/server on Docker Hub. The forgejo pin rests on the nixpkgs of the lock, which builds 17.0.1, because the registry read of codeberg.org served a stale page to the leg. Alternatives that lost: the native units, because a spine update then rides a lock bump of nixpkgs, the vaultwarden move converts its sqlite store one way, and the forgejo move needs a check of the schema version; the owner keeps the native move as future potential. Digest pins, because a digest hides the version from a reader and an exact version tag holds the same practical immutability, and the repository already pinned exact tags, wger 2.7.0 and agentsview 0.46.1. The moving tags, because a spine image then moved outside every review. Consequences: a spine update needs one edit of one image line. The first rebuild of each spine host verifies the pull of the four exact versions, and the forgejo pull is the one check that the leg could not run. The other moving tags, among them redis, postgres, and nginx of wger, keep their tags and stay outside this ruling. Status: accepted. Reopens: a spine service moves to a native unit, or a registry rewrites an exact version tag, so a pin needs a digest.
