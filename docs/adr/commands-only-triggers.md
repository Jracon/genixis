# Plain prose starts nothing on the loop

A record of the register, made 2026-11-19. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-19, issue 525, the windowed session of the worker leg. Context: three plain-text triggers started legs of the loop: every comment on an open issue that held the `gate` label, every plain human comment on a pull request whose head branch starts with `ai/`, and every new comment that the poll fallback read on a gated issue. The owner ruled the surfaces of the loop: a person works in plain conversation, an agent works in commands, and no plain text may start a leg, because a start is an explicit act and prose is an answer. Decision: the human surface of the loop is the commands `/loop` and `/watch` on issues and on pull requests. The `gate` label retires, with its standing any-comment authorization and its role as the discovery set of the poll fallback, which now reads all open issues. One exception carries the plain-text continuation: the `needs-owner` label, which the dispatcher sets when a bound trips, on the wake rule and on the red-gate rule. A plain comment on an entity that holds the label continues that thread through the branch-state rule of a command comment, resets the wake bound, and removes the label, because a thread that the loop stopped waits for exactly the prose of a person. Alternatives that lost: plain comments on pull requests as standing nudges, because a start must be explicit and a comment on a pull request is often an answer to its worker; the `gate` label beside the commands, because its authorization duplicated `/loop` and no open issue held it at the time of the ruling; a label that grants unbounded autonomy, because the owner kept every autonomous chain inside the bound of two wakes per entity pair. Consequences: a human comment that means a start must say a command; a blocked leg that reports and stops receives `/loop` or `/watch` for its continuation, or prose when its thread holds `needs-owner`; and the owner deletes the retired `gate` label on the forge after the merge. Status: accepted. Reopens: a trigger of the loop that plain prose should start.
