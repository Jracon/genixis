# The file tree shows in the current tab only

A record of the register, made 2026-11-18. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-18, issue 508; the ruling re-rules the design of issue 234. Context: issue 234 ruled the tree toggle shared: one toggle bit, and a tree window in every tab page, because an nvim window belongs to one tab page and the tab-per-file layout of issue 196 means many tabs. The replication carried two costs: the tree state diverged between the tabs, because each tab holds its own neo-tree instance, and the replication machinery leaked tabs that hold only a tree window (issue 506). Decision: leader t t shows and hides the tree of the current tab page only. The toggle reads the windows of the current tab, so the module holds no shared state. A new tab starts with no tree, and a session reload shows at most one tree. The bare-start open, the reveal of leader t f, the scroll clamp, the sweep of issue 506, and the q and leader x close keep their behavior. Alternatives that lost: the every-tab tree of issue 234, because the divergence of the tree state and the leftover tabs stand; the buffer-tab model, one tab page with buffers, because it re-rules the layout of issue 196 and retrains the tmux tab chords; a sync of the state between the per-tab instances, because neo-tree keys its state by tab page, so the sync is unsupported custom work. Consequences: the per-tab propagation, the show on TabNewEntered, and the per-tab session restore of tree.lua are gone, and docs/keymap.md and lib/keymap.nix state the current-tab toggle. Status: accepted. Reopens: a workflow needs the tree in several tabs at once, or neo-tree gains one tree state across tab pages.
