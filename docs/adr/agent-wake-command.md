# The agent wake command narrows the self-trigger rule

A record of the register, made 2026-11-19. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-19, issue 525, the windowed session of the worker leg. Context: the self-trigger rule of the dispatcher ignores every comment of the agent login, so a reviewer verdict with blocking findings — the one comment that names what the worker must do next — started nothing, and the worker of that pull request continued only when the owner commented, when CI failed, or when the owner looped the issue again. The design record of 2026-11-15 on issue 392 weighed an agent-comment trigger and set it aside on three grounds: spine growth, loop load, and a stop that buys nothing. Decision: the final comment of a leg can wake exactly one other leg. The wake is the reserved command `/wake` as the first word of the final comment of a leg, the comment that releases the in-flight entries of its entity, and no other agent comment triggers. The command takes no arguments: the released entry carries the routing, so a reviewer verdict wakes the worker nudge of the same pull request, and the final comment of a worker or nudge branch wakes the issue that the `Refs` keyword of the branch's open pull request names. The wake enqueues the same event shape as a human comment and runs under a bound of two wakes per entity pair until a human act resets, with the red-gate rule as the template; the trip sets the `needs-owner` label and comments with the name of the owner. The issue answered each ground of the record of issue 392: the release path already runs, so the spine grows by one grammar check; every wake flows through the standing pacing layers; and the wake removes one human stop, against no new stop. Alternatives that lost: any agent comment as the trigger, because no mechanical bound holds a confused leg, against the storm record of issue 267; labels alone as the trigger, because a label names a state that outlives the wake and cannot carry the one-shot form of one leg waking one leg; a wake command with an entity argument, because the entity thread already names the target and an argument lets a creative leg summon an arbitrary entity; a timer sweep that scans for verdicts, because it re-reads every entity inside an event path that the webhook already owns. Consequences: the verdict-to-worker continuation and the composition handoff run without a human comment under the bound; a handoff from which no target derives posts one comment and wakes nothing; the dispatcher gains its first label write, the `needs-owner` mark through `tea issues edit`; and the self-trigger rule narrows but stands for every comment that releases no entry. Status: accepted. Reopens: a wake path that starts a leg outside the pacing layers, or a bound trip that no human act resets.
