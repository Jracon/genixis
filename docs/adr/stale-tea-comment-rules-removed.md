# The stale tea comment rules are removed

A record of the register, made 2026-11-18. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-18, issue 509, item 5 of the decision record of the windowed session. Context: record 13 put the removal decision on the stale `tea comment` allow rules into stage 5 of issue 166, and that stage closed with no decision. The flag-first allow rule `tea comment --repo jracon/genixis *` and its two deny rules for the delete forms served the comment form that issue 226 replaced with the verb form `tea comments add`. No usage record shows a consumer of the old form. Decision: the owner ruled the removal of the three rules, and the change of issue 509 executes it. The project layer of this repository holds none of the three rules. The verb form `tea comments add` carries each comment in the working repository, and the forge hook allows that form. Alternatives that lost: keeping the three rules, because no consumer remained and a rule with no consumer widens the allow surface for nothing. An allow rule for the flag-first form in the user layer, because the hook already allows the verb form in each working repository, and a comment on another repository from a session of this machine stays a decision of that session. Consequences: a session in another project that posts a comment on jracon/genixis stops at a prompt, because no allow rule covers the flag-first form outside the working repository. docs/agent-context.md names the removal in the section on the rules of a repository. Status: accepted. Reopens: a consumer that needs the flag-first comment form from a project other than the working repository.
