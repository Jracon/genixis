# The sandbox tier builds on NixOS only

A record of the register, made 2026-11-19. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-14, issue 393, the dispositions of the campaign. Context: phase 5 of issue 74 planned the sandbox tier for two platforms: transient systemd units on NixOS and a Seatbelt profile on Darwin, with the proxy on both. The stage 0 record of issue 166 kept the phase as written. The Darwin half has no consumer: no headless leg runs on Darwin, because the macOS Local Network gate blocks the LAN address in a daemon chain (docs/services.md, the naming chain section), and a person oversees each interactive session. Decision: the sandbox tier builds on NixOS only. The Darwin half is cut: no Seatbelt profile is generated, and no proxy runs on Darwin. The build of the tier sits in the sandbox work issue of the campaign of issue 393. Alternatives that lost: the tier as written, because the Darwin half serves no session and the Necessity Test of use removes it; the microVM tier as the primary mechanism, because the transient unit and the proxy are the plan of record and the microVM stays the fallback. Consequences: the microVM deferral of docs/services.md names the unit sandbox and the proxy as its trigger. The rule that no sandbox option enters a user unit of the dispatcher (its README, the environment of a leg) stays in force until the tier lands, because every sandbox option in a user unit breaks the ssh of the legs through the implied user namespace. Status: accepted. Reopens: a headless leg that must run on Darwin.
