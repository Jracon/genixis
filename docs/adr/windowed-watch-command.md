# The windowed start is its own command

A record of the register, made 2026-11-19. The index of the register sits in docs/decisions.md.

Made: the owner, 2026-11-19, issue 525, the windowed session of the worker leg. Context: the windowed route of issue 470 rode the loop command as the reserved word `window` behind it, in the form `/loop window`, and machine decision 26 of the dispatcher README recorded that form. The owner ruled the vocabulary of the loop: a command takes no word arguments, and each variant is its own command. The word `window` also named the mechanism, not the behaviour, and the name `/interactive` would collide with the interactive-leg concept of issue 473, a session that a person drives mid-run, while a windowed leg drives itself and only its prompts wait. Decision: the watched start is the command `/watch`, the first word of the comment, with the same grammar as `/loop`: the prose of the ruling may sit on the same line or on later lines. The reserved word `window` is gone, and `/loop window` starts a plain leg. The prompt entry point takes the word `watch` in the place of the old argument. Alternatives that lost: keeping the reserved word behind the command, because the vocabulary of the loop stays one word per command and a word argument reopens the form question for every later variant; `/interactive`, because the name belongs to the concept of issue 473 and a windowed leg is not driven by a person; `/window`, because it names the mechanism of the view window and leaks the implementation into the vocabulary. Consequences: the receiver parses `/watch` as a first word on issues and on pull requests, the poll fallback parses the same word, and the recipe of the README prints the watched brief with `prompt worker N watch`. Status: accepted. Reopens: a second variant of a command of the loop that cannot be its own command.
